# 留德小栈｜功能使用与发布手册
2026 年 9 月 6 日修订 · 九月功能更新 · 学生端 / 管理员端

## 本轮更新重点
首页先浏览、使用时自愿登录；学校与专业联合搜索；成绩单上传与校对；个人经历分项填写和复用；简历与动机信结构稿导出；无时段咨询预约；课程反馈；管理员资讯审核发布。

## 当前验收范围
后端及小程序逻辑自动化测试 48 项通过，另有安全区、长文本、弹层及源码解析检查 14 项通过。此前微信模拟器巡检覆盖 28 个页面，游客浏览和自愿登录流程通过。已将合成资料导出为中文匹配报告、英文简历、德文动机信，渲染检查字体与表格。
这些结果不等于覆盖了所有真实手机、所有成绩单格式或高并发场景。首次发布前仍需用真实 iPhone 和 Android 完成关键流程抽测；模拟器网络与微信授权不完全等同于正式环境。

## 四项不能误报为完成的事项
1. 微信后台的“深度合成 - AI问答”服务类目，需要管理员补充并按平台要求提交资质。代码中的 AI生成标识不代替类目配置。
2. 微信托管《用户隐私保护指引》第三、第七条的联系方式需在微信后台改为 liudexiaozhan。小程序页面已提供正确联系方式，但不能自动替你修改平台托管内容。
3. 公众号直接跳转需配置关联公众号的原始 ID（gh_ 开头）；只有公众号名称或微信号不足以调用。未配置时保留复制名称与海报指引。
4. 当前文书后端为本地事实整理，不是完整的中文转德语/英语翻译服务。待翻译内容会明确标出；须补齐目标语言或由老师翻译审核后使用。

## 保持关闭的功能
在线收费、独立公司 SQL 数据库暂未启用，接入位置保留。现有腾讯云 COS 用于文件及备份，不等同于已经部署了独立关系型数据库。直播目前保留 HTTPS 入口和课程记录，不代表已接入推流、连麦、回放平台。

# 01｜学生：院校与专业匹配
## 浏览与搜索
首页或搜索页输入学校名、专业英文名或常见专业中文关键词。专业库结果可进入学校详情，查看现有专业简介、申请条件和来源。学校卡片显示收费标签；学校或项目可能存在不同收费政策，须按目标项目当期官网确认。
专业介绍来自现有资料库，不是实时抓取。申请季、截止日期提示已中文化；原始专业名称及部分官方英文描述保留，避免用未经核验的翻译替代招生要求。

## 匹配流程
1. 基础背景：按星号填写必填项。学校、专业、申请方向等会影响推荐结果。
2. 院校目标：选择申请层次、专业方向及偏好。
3. 课程经历：可打开“个人简历信息表”分项填写，后续简历可复用。
4. 课程信息：此处只上传成绩单图片或 PDF，不必再上传调查表或简历。单份成绩单按页面上限提交；也可手动补充核心课程。
5. 校对后生成：核对课程名、成绩、学分，确认后生成匹配结果。识别不完整时补充或修正，不要直接接受错误课程。

## 成绩单保存说明
登录后的成绩单上传会保留原始文件，授权管理员可在学生资料库查看、保存并复核。将文件从匹配列表移除，不等同于从资料库删除；删除原件请到资料库操作。
用户只能访问自己的资料；他人账号不能通过文件链接读取资料。文件预览依赖系统支持的格式，无法在线预览时可下载后用对应软件打开。

## 如何理解匹配度
匹配度基于填写的背景、课程证据和项目条件进行规则比对，不是学校录取概率，不代表一定申请成功。材料完整度不足时，结果仅作初筛。申请前由本人或顾问核对学位、先修课、语言、截止日期及费用。
报告以表格导出，包含学校、专业、项目简介、要求、课程证据、匹配建议与免责声明。不要仅凭一个百分比决定申请。

# 02｜学生：简历与动机信
## 简历：先整理事实，再生成文件
打开“留德简历”，点击“按个人简历信息表填写 / 复用经历”。分项包括大学及交换、中小学、语言考试、工作实习、科研项目、论文、奖励、课外活动、技能证书和兴趣。参考问卷仅用于字段结构，不会将参考学生的私人信息作为默认内容。
同一微信账号已经保存的信息会复用；信息不会复制给其他账号。分项表会回填概要字段，优先检查和修改已有内容，不必重复填写同一段经历。

## 日期填写规则
教育、工作等填写真实起止年月。仍在持续才勾选“至今”，德文导出显示 bis heute，英文显示 present；已毕业或离职不能为了填空窗写成至今。
分项时间轴发现空档时，填写真实的备考、求职、休息等说明，不要虚构经历。旧版自由文本经历不能完整自动校验，导出前仍需人工逐段检查日期。

## 动机信
已移除“目标学校的文书或申请要求”填写字段，但申请人仍需自行核对学校正式要求。篇幅可选 1 页或 2 页（推荐），学校另有规定时以其规定为准。
生成内容和学生填写内容强相关。写清课程或项目、时间、本人职责、方法、结果及与目标专业的关系。聚焦真实的学习、学术和职业目标，不以移民为申请动机，也不要虚构意图或经历。

## 语言、预览与导出
选择 Deutsch 或 English，生成后先看专业排版预览和待校对提示。当前后端不会完整翻译任意中文段落；不支持的内容显示待翻译标记，原文仍保留在调查表。
PDF 嵌入中西文字体，减少手机缺字体造成的乱码；Word 可编辑，但不同设备和编辑器可能重新分页。动机信页数限制针对 PDF，内容过长时提示精简，不会静默截断正文。
正式递交前，确认没有待翻译占位、没有虚构内容，并核对姓名、联系方式、日期、学校名、语言、字数和格式；建议由文书老师审核。AI生成标识及水印不是学校审核或录取保证。

# 03｜学生：课程、预约与其他入口
## 免费课程
已发布且标为免费公开的课程可直接浏览学习，不强制先登录。未设置视频或直播入口的占位课程不作为游客可播放课程展示。
如果课程加载失败，检查网络后重试；仍失败时通过课程反馈或客服说明课程名称、设备和现象。不要把“课程列表存在”理解为视频已成功上传腾讯云。

## 课程反馈
登录后通过课程反馈进入私信，将课程名称和问题发给老师，老师在后台回复。当前采用私信形式，不是公开评论区；其他学生不能看到你的反馈内容。

## 咨询预约
填写姓名、联系方式、希望联系的老师和咨询内容后提交。联系方式可填手机、邮箱或微信号；不选择日期或时段，也不承诺某个时间已被预订。
提交成功表示待老师联系确认。已有待联系申请时不重复新建，补充内容可通过客服发送。老师联系后可在后台更新状态。

## 关于我们与公众号
“关于我们”展示原海报，可点击查看完整海报。咨询微信为 liudexiaozhan。宣传中的历史案例、人数等信息需由公司自行确保真实有效。
配置关联公众号 gh_ 原始 ID 后，支持的微信版本可打开公众号主页。未配置、版本不支持或调用失败时，使用复制公众号名称和海报指引，不会伪装成已经成功跳转。

## 登录与隐私
首次进入以公开浏览为主。保存资料、预约、发送私信等操作再由用户选择登录，首页不自动要求手机号、头像或昵称授权。
退出登录后仍可浏览公开内容；内存中的个人资料和推荐记录会清除。同一账号的本地保存记录用于下次复用。请勿在问卷中填写非必要身份证号、银行卡、验证码或密钥。

# 04｜管理员：课程与学生服务
后台地址：https://liude-xiaozhan-mp-backend.onrender.com/admin

## 课程上传与发布
1. 使用有效管理员访问令牌登录。不要将令牌放入公开截图、代码或学生群。
2. 新建或编辑课程，填写类型、名称、简介、标签及状态。
3. 录播课上传本地视频，或填写已有 HTTPS 视频地址。后台本地上传支持分片，单文件上限 512 MB；上传完成后还要保存课程。
4. 公开免费课程勾选“免费公开”。指定学员授权课程不要同时勾选免费公开。
5. 设置“已发布”并保存，刷新列表，使用“测试播放”验收；再用未登录的小程序检查免费课程可见性。

## 视频到底存在哪里
| 后台显示 | 实际含义 | 管理员操作 |
| --- | --- | --- |
| 后端内置（不在腾讯云） | 随代码提供的示例视频 | 无需在 COS 中寻找同名文件 |
| 腾讯云 COS | 检查到公司 COS 对象 | 到课程视频目录核对 |
| 服务器本地 | 本地文件，不代表已在 COS | 确认持久化或重新上传 |
| 外部链接 | 视频由该链接所属服务托管 | 核对链接和播放权限 |
| 待核实 / 文件缺失 | 无法确认或文件已不存在 | 重试检查，必要时重新上传 |

## 学生资料库
按学生记录查看文件，点击“查看”在线预览支持的格式，点击“保存”下载原始文件。成绩单需要管理员复核课程、成绩及学分，不应只看 OCR 结果。原始文件、生成文书和元数据的存储方式不同，COS 不是传统的表格数据库。

## 预约与私信
预约管理查看待联系申请，按学生留下的方式联系后再点击“标记已联系”，不要提前标记。企业群提醒如已配置，会仅提示有新申请；详细联系方式和内容进入后台查看。
客服消息查看课程反馈及其他咨询，回复后学生可在自己的消息页查看。账号权限配置与数据库启用不是一回事。

# 05｜管理员：资讯审核与数据说明
## 发帖流程
管理员在“资讯”新建标题、正文，可附 HTTPS 官方来源。保存后为草稿，提交审核后为待审核；确认内容准确再审核发布，随后首页搜索栏下方的滚动资讯和资讯页可见。
编辑已发布内容会回到草稿，需要重新审核。学生不能发帖或审核。当前支持管理员自己审核；如果公司要求编辑与审核必须是两个人，需要后续增加角色分离。
发布 APS 等政策时核对发布日期、生效时间和官方来源。不要把示例文字、过期政策或尚未核实的消息发布为正式通知。

## 使用统计的口径
统计来自后端记录的真实操作事件，不使用随机人数。新增统计排除已标记的管理员和测试事件；游客浏览不会作为已识别学生计数。
历史未标记的内部测试、共享设备及未上报事件可能影响统计，因此不能把后台数字当作审计后的商业活跃人数，也不能承诺其覆盖全部使用行为。生成、导出、匹配、课程等事件需按各自口径阅读。

## 存储与收费边界
课程视频、学生上传资料和生成文书按现有 COS 配置保存；课程、预约等业务记录仍以当前后端记录与 COS 备份机制运行。新建独立数据库、迁移历史数据、备份恢复演练和高并发验证尚不等于完成。
收费入口保持未启用。不得因为已经有公司银行账户就宣布微信支付可用；微信支付商户、证书、回调和订单联调是独立工作。

## 故障反馈建议
记录：页面名称、操作步骤、发生时间、微信版本、手机型号、错误截图。资料问题通过受控后台排查，群截图遮挡学生姓名、联系方式、成绩单和令牌。
建议每次更新前至少检查：游客首页、免费课播放、成绩单校对、资料下载、预约提交、私信回复、文书导出，以及管理员资讯审核。

# 07｜提审与正式发布流程
## 提审前必须完成
先确认 Render 已运行本轮后端版本，再上传本轮小程序代码。后台单独部署不会更新用户手机里的小程序前端。
在微信后台补充审核要求的服务类目与资质，更新隐私保护指引；需要公众号直跳时提供并配置 gh_ 原始 ID。以上平台项目未操作，不能仅凭本手册宣称完成。
用体验版在 iPhone、Android 各完成一次关键流程，尤其是首次无登录浏览、相册/文件授权、资料下载和 PDF 字体。正式发布仍以微信审核结果为准。

## 按此顺序操作
1. 后端：确认 GitHub 中已保存本轮代码，Render 完成部署，健康检查版本为 20260905-review-functional-update。COS 仍启用，支付和独立数据库仍关闭。
2. 前端：在微信开发者工具导入本次“用户版小程序”目录或发布压缩包，AppID 保持原小程序，不新建小程序。
3. 本地检查：先退出登录再打开首页，确认可浏览；再按需登录，测试填写、预约、私信和导出。
4. 上传体验版：使用高于线上及已有开发版本的版本号，备注填写本轮更新内容。不要沿用“首次发布”的备注。
5. 微信后台：同步隐私指引、服务类目及要求的资质，选择实际符合的测试方式。不要提供虚假测试账号或将管理员令牌用于审核。
6. 真机验收：核对小屏、大字号、安全区、键盘弹起、长课程名和 PDF 预览；异常记录具体机型与操作。
7. 提交审核：附真实功能截图和本轮版本说明。审核通过后再执行正式发布；用户仍通过原小程序入口或原二维码进入。

## 本轮尚需提供的信息
公众号原始 ID（gh_ 开头）用于直跳配置，不需要在聊天中提供公众号密码或 AppSecret。文书完整翻译能力需另行确定翻译服务或老师审核流程；当前结构稿不能代替翻译验收。
Render 或微信后台登录失效时，由账号持有人完成登录与验证码。开发者工具如询问信任项目，请由使用者确认本地项目来源。

## 可用于审核的版本说明
优化首次浏览与自愿登录流程，完善院校专业搜索和成绩单校对，调整简历与动机信结构、导出与 AI生成提示，新增无时段咨询预约、课程私信反馈和管理员资讯审核，改进资料查看保存及页面适配。
